# ステップ2: 1週間のテスト送信(あなた宛てだけ)

目的: 毎朝の通知の「文面」「点数」「動き続けるか」を、本番の前に確かめる。送り先は、あなたのチャット(テストの部屋)だけ。

## 始める前(1回だけ)
README の「初期設定」の1〜6を終える。特に次を確認する。
- `sendTestPing` で、テストの部屋に接続テストが届く
- 「設定」タブの「送信モード」が `test` になっている(`prod` にしない)
- `runAllNow` で、1通届く(最初の取り込みなので、新着は0件。ウォッチも「基準を保存」だけ)
- `installTriggers` を実行済み。Apps Script の「トリガー」に `collectDaily`(8時台)と `sendMorning`(9時台)がある
- トリガーの失敗メールを有効にした(Chatwork が止まった日にも気づくため)

## 毎日(1分)
| 見るもの | 確認すること |
|---|---|
| Chatwork の通知 | 9時台に1通。スマホで1画面で読めるか。リンクが開くか |
| 通知の上の方 | 「取れなかった情報源」が出ていないか(出ていたら、「実行の記録」のエラーを見る) |
| 新着(高)の中身 | 本当に物件王に関係があるか。関係が薄いのに出ていれば、点数の理由を見て、キーワードを直す |
| 「制度の更新」 | 本当に変わった内容か。毎日変わる部分の誤検知なら、「ウォッチ」の除外パターンに足す |

## 調整のしかた(コードは触らない)
- 「高」が多すぎる/少なすぎる → 「設定」タブの「しきい値」の「高」の値を上げ下げする(今は30)
- 関係ない制度が上に出る → 「設定」タブに、引く条件(マイナスの点数)の行を足す
- 出てほしい制度が「中」に落ちる → 「設定」タブで、その制度名のキーワードを足す(点数30)
- 直したら、次の `collectDaily` で、全件の点数が付け直される

## 7日後に見る
`weeklyHealth` を実行すると、直近7日の「収集できたか」「エラー」「通知の結果」「更新の件数」が出る。
合格の目安(仕様 11-3):
- 7日連続で、収集と通知が失敗なく動いた(`okDays` が 7)
- 取れなかった日は、通知に「取れなかった」と出ていた
- 通知が、毎日、スマホで1画面に収まっていた

結果を見せてください。点数のしきい値と文面を一緒に調整してから、ステップ3(チームへ)に進みます。
