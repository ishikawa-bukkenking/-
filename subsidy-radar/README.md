# 補助金レーダー(物件王・社内専用)

補助金・助成金の情報を、毎日自動で集め、Chatwork に朝9:00に1通でまとめて通知する。
Google Apps Script(無料)+ スプレッドシート「補助金レーダーDB」。仕様は `../docs/spec.md`。

## しくみ

| 時刻 | 関数 | 内容 |
|---|---|---|
| 8時台 | `collectDaily` | Jグランツ API と、ウォッチ対象ページを取得 → 点数 → シートに保存 |
| 9時台 | `sendMorning` | 新着・締切・制度の更新を1通にまとめて Chatwork へ(同じ日は1回だけ) |

- 同じ日に何回実行しても、データは増えず、通知は2通にならない(冪等)
- 送信できたものだけ「通知済」にする。失敗した日は、翌日に持ち越される
- 画面(ウェブアプリ)は作らない。見るのはスプレッドシート(絞り込み・並べ替えはシートの機能)

## 使っている情報源と、守っているルール

| 情報源 | 方法 | 確認したこと |
|---|---|---|
| Jグランツ(デジタル庁) | 公開 API `api.jgrants-portal.go.jp/exp`(認証なし) | 依頼者が利用を承認。1日1回、一覧は検索語18個、詳細は新着・変更分のみ(1回40件まで)、1リクエストごとに1.5秒待つ。失敗したら、その場で止める。ポータルのページは robots.txt で禁止のため取得しない(リンクとして出すだけ)。出典を付ける |
| 厚生労働省の指定ページ | ページ取得(ウォッチ) | robots.txt は `/cgi-bin/` と `/images/` のみ禁止。1ページ1日1回、間隔3秒。RSS は利用条件のため使わない |

| 厚生労働省 新着情報(お知らせの見出し) | ページ取得(`/stf/new-info/index.html`) | robots.txt は許可。サイトの利用条件は公共データ利用規約(PDL1.0)で、出典を付ければ利用可。1日1回・1ページ。取るのは見出し・分類・公開日・リンクだけ。RSS は使わない |

**まだ使わないもの**(利用条件の確認ができていない): J-Net21、中小企業庁・経産省・国交省、愛知・岐阜の労働局、デジタル化・AI導入補助金のサイト(ウォッチ一覧に OFF で入れてある)、自治体のページ。経産省・中小企業庁は自動アクセスが 403 で断られるため使わない。

## 通知で分かること

| 区分 | 何が分かるか | 元になるもの |
|---|---|---|
| 新着 | 新しく出た補助金(名前・上限額・補助率・対象・内容の1文・受付期間) | Jグランツ |
| 締切が近い | 7日・3日・前日 | Jグランツ |
| 条件の変更 | 公開中の制度の「受付終了 11/30 → 12/28」「上限額 200万円 → 250万円」など | Jグランツ(前回との差) |
| 公式のお知らせ | 助成金・補助金・最低賃金などの見出し(例: 産業雇用安定助成金の特例) | 厚労省 新着情報 |
| 公式ページの更新 | 見ているページで「変更: 助成率 60% → 75%」「追加: …」 | ウォッチ |

お知らせの絞り込みは、「設定」タブの `お知らせ語`(含む語)、`お知らせ除外`(除く分類)、`お知らせ除外語`(除く語)で直す。見出しの一覧は「お知らせ」タブ。

## 保存・表示するもの

タイトル、受付期間、上限額、補助率、対象、ごく短い抜粋(1〜2文)、元のリンク、出典。**本文は保存しない。**
ウォッチは「行のハッシュ+先頭40文字」だけを持つ(変わった行の抜粋を出すため)。

## Jグランツ API で取れないもの(推測で埋めない)

- **実施機関・公開日・更新日**: API に無い。空欄のまま
- **上限額が 0**: 未設定のことがあるため、「要確認」(0円とは出さない)
- **「予定」(まだ始まっていない公募)**: 募集中だけを取るため、取れない(全期間の取得は1.6MBと重い)
- 日付は UTC で届くため、日本時間に直している

## 初期設定(最初の1回)

前提: Node.js、`npm i -g @google/clasp`、`clasp login`(物件王の Workspace アカウント)

```bash
cd subsidy-radar
clasp create --type standalone --title "補助金レーダー" --rootDir src
```

1. Apps Script の画面で `setup` を実行 → スプレッドシート「補助金レーダーDB」が新しくできる
2. **スクリプトのプロパティ**(プロジェクトの設定 → スクリプト プロパティ)に入れる。**チャットやファイルに書かない**
   - `CHATWORK_TOKEN` … Chatwork の API トークン
   - `CHATWORK_TEST_ROOM_ID` … テストの部屋のID(最初は依頼者のチャットだけ)
3. `sendTestPing` を実行 → テストの部屋に接続テストが届けば成功
4. 「設定」タブの「送信モード」を `test` にする(最初は `dry`=送らない)
5. `runAllNow` を実行 → 収集して、テストの部屋に1通届く。最初の取り込みは「新着」にしない(大量通知の防止)
6. `installTriggers` を実行 → 毎日、8時台に収集、9時台に通知
7. スクリプトの編集者は、必要な人だけにする。トリガーの失敗メールは、Apps Script の「トリガー → 通知を設定」で有効にする

## 送信モード(安全装置)

| モード | 動き |
|---|---|
| `dry` | 送らない。文面を「通知の履歴」に残すだけ |
| `test` | `CHATWORK_TEST_ROOM_ID` の部屋にだけ送る |
| `prod` | `CHATWORK_PROD_ROOM_ID` の部屋へ送る。**依頼者が確認してから**、プロパティを入れ、モードを変える |

## 運用で直す場所(コードは触らない)

- **キーワードと点数**: 「設定」タブ(区分=キーワード)。範囲は空=全項目、`title` / `industry` / `area` / `industry_only`
- **しきい値**(高・中の境目): 「設定」タブ(区分=しきい値)
- **情報源のON/OFF、通知の時刻、該当なしの日に送るか**: 「設定」タブ
- **ウォッチするページ**: 「ウォッチ」タブに行を足す(有効=ON)。種別は `html`(変わった行の抜粋を出す)/ `html_hash`(抜粋なし。変わったことだけ知らせる)/ `pdf`。ページの作りが変わって取れなくなったら「範囲の開始目印」「範囲の終了目印」「除外パターン」を直す
- 取れなかった情報源は、毎朝の通知の上部に出る。詳細は「実行の記録」タブ

### 情報源を追加する手順
1. 利用規約・robots.txt・API 条件を確認する(確認できなければ使わない)
2. API/RSS なら、`src/Jgrants.js` を参考に `src/<名前>.js` を作り、`Main.js` の `runCollect_` に1行足す(取り出す部分の指定は、そのファイルの先頭か `Config.js` に集める)
3. ページの変化検知だけなら、「ウォッチ」タブに行を足すだけ

## Apps Script の上限と、予想の使用量(Workspace / 個人。Google 公式)

| 項目 | 上限 | 1日の使用量(実測・予想) |
|---|---|---|
| URL 取得の呼び出し | 100,000 / 20,000 | 約 60〜70(一覧18 + 詳細40まで + ウォッチ3 + Chatwork1) |
| 1回の実行時間 | 6分 | 収集 約3分(初回は詳細を40件ずつ取るため数日かかる)。通常の日は約1分 |
| トリガーの合計時間 | 6時間 / 90分 | 約5分 |
| メール受信者数 | 1,500 / 100 | 0(メールは使わない) |
| Chatwork API | 5分あたり300回、同じ部屋に10秒あたり10回 | 1 |

実測: 実データで、初回の収集(一覧18回+詳細60件+ウォッチ3ページ)は 221秒(81回の呼び出し)。上限を40件に下げた。

## テスト

```bash
node --test tests/logic.test.js tests/integration.test.js
```

- `logic.test.js` … 日付の読み取り(和暦・年なし・随時)、点数、重複、変化検知、通知の文面
- `integration.test.js` … Google のサービスの代用品で、収集 → 通知を通す(冪等、失敗時の挙動、Chatwork の安全装置)
- 実際の Google・Chatwork に対する確認(トリガー、送信)は、上の手順で手動で行う
